# 日页 0.2.2

简洁的 Windows 本地待办、事项反思与日记工具。数据保存在本机，无账号、无服务器、无全局快捷输入。

## 使用

从 [GitHub Releases](https://github.com/heiyiy/daypage/releases/latest) 下载便携版 exe 后双击运行，不需要打开终端或运行 Node.js。也可以下载安装包，安装后从开始菜单打开。本地已有的 `日页.exe` 和 `日页安装包.exe` 对应这两种使用方式。

- 待办：输入后按 Enter 添加，勾选完成。文字加粗，支持原色、白底黑字、黑底白字及三档背景透明度。
- 操作：每条待办右侧“⋯”中修改标题、上移 / 下移、删除；标题需点击保存。删除的条目可在“已删除”中恢复。
- 事项反思：展开“⋯”后填写，完成中文组词并停止输入约 500 毫秒后自动保存；保存时保留原输入框和焦点，不重建列表，期间继续输入的文字会在下一次保存；失败保留草稿，可点击“保存反思”重试。历史页中也会显示已保存的反思。
- 跨天：旧任务留在原日；今天的“此前未完成”中点击“安排到今天”，建立今天的安排。原日显示结转去向；不同日期的完成状态和反思互相独立。
- 撤销：清单底部撤销所有窗口最近一次已保存的数据操作，最多保留 50 步，重启后仍可使用。包括新增、编辑、完成状态、排序、删除恢复、事项反思、日记和结转。遇到后续修改冲突时拒绝覆盖；恢复整个备份不进入撤销栈，改用恢复前备份回退。
- 小组件：拖动左上角日期区域移动，边缘缩放；保持在普通应用窗口下方，打开小窗口时未遮挡部分仍然可见；覆盖它时自然被遮住，移开窗口后重新露出；“×”手动隐藏到托盘。位置、大小、配色和透明度会记住；正常关闭 / 退出时保存普通窗口布局。
- 月历：“日历”打开独立窗口，一月一页，日期格显示前三条待办、剩余数量和完成统计。点击日期展开完整待办与当天日记 / 反思。
- 历史：默认只读，点击“编辑这一天”后修改。日记停止输入约 500 毫秒自动保存，切换日期 / 关闭前也会保存，失败时保留文字并阻止离开。
- 设置：日历右上角“设置”中开启或关闭开机启动、更改备份目录、立即备份、恢复和导出。默认不开机启动；便携版启用后请保持程序路径稳定，移动后重新开关一次。
- 退出：托盘右键“退出”。退出、恢复和撤销前会检查两个窗口的草稿；未添加的新待办需要先添加或清空，标题需要保存或取消。

小组件通过 Windows 窗口事件和每 750 毫秒一次的轻量复查维护桌面层级，不再随应用焦点隐藏；只有层级需要恢复时才调整，平时输入不受影响。恢复时不抢焦点、不保持置顶。手动隐藏后不会在回到桌面时自动重现，可从托盘“待办”重新启用桌面显示。日历窗口按需创建，关闭后释放。最大化 / 最小化不会覆盖普通窗口布局；断开的屏幕位置会回到可见区域。

## 保存、备份和恢复

数据库：`%APPDATA%\com.personal.daypage\daypage.sqlite3`，布局：同目录 `window-layout.json`。程序与数据分开，替换可执行文件不删除数据。

当前数据库版本 3。升级前会生成 `daypage.pre-v3.sqlite3` 一致性快照；旧版本 1 升级还会生成 `daypage.pre-v2.sqlite3`。

自动备份默认在数据目录的 `backups` 下，每天一个 `daily-日期.sqlite3`，每次成功保存后更新当天快照，保留最近 30 份；启动、午夜和恢复焦点时也检查当天备份。手动备份和恢复前备份不参与自动清理。可在设置中换到其他磁盘；备份失败会在清单和设置中提示，本地保存的内容仍保留。

恢复支持 SQLite 备份和本程序导出的 JSON。先检查格式、版本、完整性和关联，再生成 `before-restore-时间.sqlite3`，最后在事务中替换待办、事项反思和日记，保留当前设置。恢复失败不替换原数据；恢复会清空撤销历史。JSON 包含所有任务、每日安排、软删除内容、反思、日记及结转关联，适合完整恢复；Markdown 按日期导出，适合阅读。

## 安装与升级

安装包采用当前用户安装，无需管理员权限。安装 / 升级前从托盘退出正在运行的旧版。安装包覆盖程序文件，应用标识保持 `com.personal.daypage`，数据库升级前自动备份。

Windows 通常已装 WebView2；缺失时安装包会在线补装，首次安装需联网。日常使用离线即可。卸载时保留应用数据；如在卸载界面主动选择删除应用数据，会删除该账户的默认应用数据目录，请先导出或备份。

## 开发与验收

```powershell
npm.cmd install
npm.cmd run tauri dev
cargo test --manifest-path src-tauri/Cargo.toml
npm.cmd run tauri build -- --bundles nsis
```

正式程序：`src-tauri/target/release/daypage.exe`。安装包：`src-tauri/target/release/bundle/nsis/`。

真实 WebView2 验收脚本：`scripts/widget-smoke.cjs`。设置 `DAYPAGE_PLAYWRIGHT_MODULE` 指向本机 Playwright，再运行 `node scripts/widget-smoke.cjs`。脚本使用专用数据库、WebView2 目录、UUID 测试启动项与本地端口 19383，只关闭自身测试进程；文件对话框由 `scripts/native-dialog.ps1` 操作。测试结束删除测试启动项。开始前退出正在运行的日页，避免单实例拦截。

测试隔离变量 `DAYPAGE_DATA_DIR`、`DAYPAGE_AUTOSTART_VALUE` 仅用于验收，正常使用无需设置。截图和验收记录位于 `verification/`。内存测量包含 WebView2 子进程与调试开销，不能用可执行文件大小代替常驻内存。

真实中文输入法选词、多屏拔插、休眠恢复，以及另一台干净 Windows 上的首次安装，仍需要相应设备环境的人工检查。

桌面显示验收：设置同样的 `DAYPAGE_PLAYWRIGHT_MODULE` 后运行 `node scripts/desktop-smoke.cjs`。测试使用独立数据，期间会短暂最小化窗口、点击测试窗口，并发送 Win+D，返回桌面后不会补点桌面，请勿同时操作鼠标键盘。
